# 时间规则兼容与复核

上游来源：ac381acf4bf41204b97bb26b4c58c83275877a2e。

日内区间采用 `>= start && < end`，跨午夜区间采用 `>= start || < end`。
起点包含，终点不包含；相同起止值表示空区间。小时、分钟、星期、月份、日期均校验整数和各自取值范围。

例如 `9–12`、倍率 2：08:59 使用原价，09:00 使用两倍价格，12:00 恢复原价。
`21–6`、倍率 0.5：21:00 开始半价，次日 06:00 恢复原价。
可视化生成和解析以测试中的表达式为契约，混合请求条件与多个规则组保持往返一致。

旧库保存的是实际表达式。升级不会自动改写存量计费配置，不回算或修改历史账单。
曾由旧编辑器生成的日内 OR（例如 `hour("UTC") >= 9 || hour("UTC") < 12`）实际上全天为真。
新的可视化编辑器会按区间含义生成 AND；只有显式保存设置后才持久生效。

上线前应在脱敏配置副本中盘点 `ModelBillingExpr`，筛出同一时间函数、同一时区、起点不大于终点的 OR 区间，逐条核对原业务意图。
不能把所有 OR 自动改成 AND：跨午夜 OR 正常，也可能存在管理员手写的全天规则。
确认应修正的规则后，保留原表达式和修改记录，在可视化编辑器重存，并核对预览与起止边界的计费结果。
不支持的复杂表达式保留原文，并可在表达式模式继续编辑。

本轮实际数据检查仅得到生产数据库版本（MariaDB 11.4.4），未读取或修改生产定价配置。真实配置盘点留在 B18 迁移演练，不得据此声明存量配置已全部修正。

代码回退不会撤销已经显式保存的表达式；AND/OR 均为旧后端支持的语法。回退设置时应从逐条保存的原表达式恢复，并保留变更期间账单，不重写历史结算。
